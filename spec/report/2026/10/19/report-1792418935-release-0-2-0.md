## Report on task: Release 0.2.0

Owner decision: release the accumulated performance work, re-running the
benchmarks on the released code (option A). Ad-hoc work, no record
archived from `plan.md`.

### Done

- Version 0.2.0 in `Cargo.toml` and `pyproject.toml` (and `Cargo.lock`);
  ADR-0005's release sentence updated; new "Releasing" section in
  `spec/docs/dev.md` covering the bump, the uv throwaway-venv recipe for
  old interpreters, the tag, the 19-artifact release workflow, PyPI
  trusted publishing, post-release verification and the yank policy.
- README corrected on the one point the benchmark work settled: the
  prefilter skips 81% of the Telegram corpus (not 77%) and the rest of
  the `str` gap is the UCS→UTF-8 encode alone, not "transcode and result
  building".
- Pre-flight: 45 Rust tests, 309 pytest and 3,484 conformance on 3.13;
  309 pytest on 3.14t; 309 each on throwaway 3.10.21 and 3.11.16 venvs
  (the release ships `cp310`/`cp311` wheels). CI green on the release
  commit before tagging.
- Benchmarks re-run on `regexus` **after** the bump, so every page names
  0.2.0 and the recorded extension hashes belong to the released code:
  main suite one guarded run (45 points, zero rejections), Telegram and
  homepage three runs each merged with `merge_runs.py`. The main page's
  nine tables were regenerated from `results.json` and its prose ranges
  updated; the two corpus pages are generated from their result files.
- Tag `v0.2.0` pushed; Release workflow built 9 x86_64 wheels (including
  the abi3 fallback), 9 aarch64 wheels and an sdist, published to PyPI
  through OIDC and attached everything to the GitHub release.
- Post-release verification from the index, not the tree: fresh 3.13
  venv, `pip install rurex==0.2.0`, `__version__ == "0.2.0"`, smoke
  script over `findall`/`sub`/bytes/`Match` accessors; then
  `pip install --no-binary :all: rurex==0.2.0` and the same smoke script
  from the sdist build. PyPI reports 19 files, the GitHub release 38
  assets (19 artifacts plus signatures/attestations).

Published results after the re-run (i5-13500): scan ×33–43, extraction
×1.8–2.0, density sweep ×1.4–4.4, pathological 72–100 ns, GIL threads
×33 → ×190, free-threaded ×24–42, position threads ×101–142 (GIL) and
×27–34 (free). Telegram `str` remains ×1.3–1.5 of `re`, bytes ×0.6–0.8;
homepage ×0.07–0.29.

### Future-task notes

  `protocol` and `threads`, unlike the main suite which records the CPU
  plus each interpreter's extension sha256. Adding the version and hash
  there would make the corpus pages traceable to a binary the same way
  the main page now is.
- [open] The main page's tables are hand-maintained; the patch script
  that rewrote them from `results.json` this session lives in the
  throwaway `var/` directory. Promoting it to `benchmarks/` would make a
  republish one command instead of a careful editing pass.
- [open] `make bench-telegram` and `make bench-html` still run one matrix
  per invocation; the median-of-3 flow is three commands plus
  `merge_runs.py`. A `--repeat` flag remains the fix.

### Tooling/process

- The release workflow fails closed before publishing if the artifact
  count is not 19, and PyPI upload uses OIDC, so no token is stored.
- A published version cannot be replaced; the tag must not be moved. The
  pre-flight wheel build is what catches a `Cargo.toml`/`pyproject.toml`
  version mismatch before it reaches the index.
- Re-running the corpora takes about 20 minutes of host time (three
  ~3-minute Telegram matrices and three ~5-minute homepage matrices plus
  merges); the main suite is about 4 minutes including both builds.
